### **版本更新紀錄：4-6**『**v1.0**』 **→** 7-2『**v2.6**』

### **給所有使用者看的「更新重點」**

- **輸入更方便**：輸入 1000、500、100 元時，可以直接打 `12`，系統會自動幫您換算成 12 張的金額。
- **不怕手滑**：現在工具會自動儲存您輸入的內容，就算不小心關掉或重整頁面，回來時資料都還在。
- **結果可微調**：計算出結果後，如果想調整鈔票組合（例如把預留金的 1000 元換成上繳區的 100 元），現在可以直接在下方的「結果微調工具」操作，不必重算。
- **零錢湊整**：新增「收納零錢對換」工具，可將上繳區的散裝硬幣與打包區的硬幣互換，方便湊成整袋。
- **微調可反悔**：所有微調工具都提供「恢復上一步」和「重置所有微調」功能，讓您安心調整。
- **徹底清空**：只要「長按」清除按鈕 5 秒，就能將整個工具（包含自訂顏色）恢復到最原始的狀態。
- **外觀優化**：修正了部分介面在手機上可能跑版的問題，並為微調工具加上了 `+` /  按鈕，操作更順手。

### **給技術人員看的「詳細更新日誌」**

### **1. 核心架構與狀態管理 (State Management)**

- **引入狀態機**：從原本直接讀寫 DOM 的方式，改為由一個中央 `state` 物件來管理所有應用程式的資料，包含 `state.inputs` (使用者輸入)、`state.results` (計算結果)、`state.exchangeHistory` (微調歷史紀錄)。
- **狀態持久化 (Persistence)**：
    - 使用 `localStorage` 來保存 `state` 物件，Key 為 `cashTool.v2.6.state`。
    - 在 `DOMContentLoaded` 時觸發 `loadState()`，從 `localStorage` 讀取並還原介面。
    - 在所有會改變狀態的操作（如輸入、計算、微調）結束後，觸發 `saveState()` 將最新狀態寫入 `localStorage`。
    - 增加了 `try...catch` 區塊，以應對 `localStorage` 不可用或資料損毀的狀況。

### **2. 輸入與驗證 (Input & Validation)**

- **張數快速輸入 (Count Mode)**：
    - 針對 1000、500、100 元的 `input` 元素，增加 `data-is-count-mode` 屬性。
    - 監聽 `input` 事件，若輸入值符合 `^\d{1,2}$` (1-2位數字)，則標記為 `true`。
    - 監聽 `blur` (失焦) 事件，若 `data-is-count-mode` 為 `true`，則將輸入值乘以對應面額，並重新格式化寫回。
- **嚴格倍數驗證**：
    - 恢復了 v1 的驗證邏輯。在 `handleAmountInput` 和 `handleBagInput` 後都會觸發 `validateAllInputs()`。
    - 此函數會遍歷所有面額，將「金額輸入框」與「袋/捆輸入框」的數值加總後，檢查是否能被該面額整除。
    - 若驗證失敗，會為對應 `input` 加上 `.input-error` class，顯示錯誤訊息，並將「計算結果」按鈕設為 `disabled`，強制使用者修正。

### **3. 全新功能模組**

- **結果微調工具 (預留/上繳)**：
    - **UI**：在結果區塊下方新增一個獨立、可收合的區塊。
    - **邏輯**：重構換算邏輯，`findValidSwapPath()` 函數確保交換嚴格發生在「預留金」與「上繳營收」兩個錢堆之間。
    - **互動**：`updateResultExchangePreview()` 會即時顯示兩區存量，並根據 `findValidSwapPath()` 的結果決定是否啟用「確認微調」按鈕。
- **收納零錢對換工具**：
    - **UI**：新增專門用於整理硬幣的區塊，可交換「上繳區」的散幣與「打包區」（即預留金的散幣）的硬幣。
    - **邏輯**：`findValidCoinSwapPath()` 函數負責判斷此交換的可行性，確保總金額不變。
- **歷史紀錄系統 (Undo/Redo)**：
    - `state.exchangeHistory` 是一個陣列，用來儲存每次成功微調後的 `results` 物件快照。
    - `performResultExchange()` 和 `performCoinConsolidation()` 會 `push` 一個新的結果狀態。
    - `undoResultExchange()` 會 `pop()` 最後一個狀態。
    - `resetResultExchanges()` 會將歷史紀錄還原到只剩索引為 0 的初始計算結果。
    - `revertToHistoryState()` 允許點擊歷史紀錄，跳轉回指定的狀態。
- **雙模式清除按鈕 (Clear Button)**：
    - `click` 事件觸發 `softClear()`，僅清除輸入值並隱藏結果區。
    - `mousedown`/`touchstart` 事件觸發 `startHardResetTimer()`，啟動一個 `setTimeout` 計時器。
    - 若在 `LONG_PRESS_DURATION` (5秒) 內觸發 `mouseup`/`touchend`，則 `cancelHardResetTimer()` 會清除計時器。
    - 若計時器順利跑完，則觸發 `hardReset()`，此函數會額外呼叫 `resetColors()` 並清除 `localStorage`。
- **顏色自訂 (Color Customizer)**：
    - **UI**：新增了顏色選擇器的 Modal 彈窗。
    - **邏輯**：使用 CSS Custom Properties (`-note-1000`, etc.)。`initColorPickers` 在載入時讀取現有顏色，`applyColor` 則在用戶操作時動態設定變數值。

### **4. UI/UX 與樣式修正**

- **版面溢出修正**：
    - 在 `.summary-grid` 中，將 `.summary-box.highlight-box` 的 `grid-column` 改為 `1 / -1`，使其永遠佔滿整行，解決了在特定寬度下被擠到下一行的問題。
    - 在結果列表 `.item` 中，增加了 `.item-content` 容器並設置 `flex: 1; min-width: 0;`，確保在空間不足時，金額文字可以被正確壓縮或換行，而不會將右側的 `meta` 元素擠出邊界。
- **Stepper 按鈕 (`+/-`)**：
    - 新增 `.input-stepper` 和 `.stepper-btn` 的 CSS 樣式。
    - 在「結果微調工具」和「收納零錢對換」的數量輸入框旁，增加了 `+` 和  按鈕的 HTML 結構。
    - 透過 `data-target` 和 `data-step` 屬性，用一個共用的事件監聽器來處理所有 `stepper` 按鈕的點擊邏輯。
- **更新提示 (Highlight)**：
    - 新增 `.update-highlight` CSS class 與 `@keyframes flash-highlight` 動畫。
    - 在微調操作成功後，`updateUI` 函數會為對應的卡片（如「營收上繳」）短暫加上此 class，提供視覺回饋。

### **5. 程式碼結構**

- **DOM 元素集中管理**：將所有頻繁操作的 DOM 元素查詢集中到 `dom` 物件中，方便管理與取用。
- **邏輯拆分**：將計算流程拆分為 `collectInputs()`（收集與加總輸入）、`calculateResults()`（核心計算）、`updateUI()`（渲染結果），使程式碼更具可讀性與可維護性。
- **全域函數最小化**：除了 `importTotalAmount()` 因歷史 `onclick` 寫法保留在全域外，其餘函數均封裝在 `DOMContentLoaded` 的事件監聽器內，避免污染全域命名空間。
